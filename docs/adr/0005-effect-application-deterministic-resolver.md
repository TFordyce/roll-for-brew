# Effect application rebuilt around a deterministic resolver over the Cast Log

## Status

accepted — rebuild spec #302 picked up 2026-08-30. Decided by the Spell-casting review wayfinder map (#278), ticket #280; sub-decisions #290–#295. Being built via #304–#321 on the shared integration branch `rebuild/effect-resolver` (branching strategy recorded in #303).

## Decision

Spell effect application is being **rebuilt**, not incrementally extended. Today a cast fans out across `layerResolution.ts` and roughly eight RPCs (modifier bucket, `submit_roll` for advantage, `apply_roll_swap/flip`, `apply_forced_reroll`, tea-maker overrides, inline WILD branches, inline `contested_negate`/`redirect`), `spell_casts.resolved_value` carries five unrelated meanings, and effect ordering is a hard-coded `flip → swap → lowest`. The rebuild replaces the fan-out with:

- **One authoritative SQL `resolve_round`** that owns all *outcome* math — modifier composition, tea-maker override, declared-number, lowest-gains-highest, hidden_modifier, ward checks, counterspell filtering, and ordering.
- **A thin eager shim** for the effect kinds that change roll *inputs* — originally four (`advantage`, `disadvantage`/`forced_reroll`, `roll_swap`, `roll_flip`); the Tier A primitives extend the set (`roll_pair_transform`, #318, is the fifth) — which record exactly what they did into the Cast Log so the resolver can still account for them. The model is deliberately hybrid, not "everything lazy": making every player roll twice to support rare advantage cards is wasteful and confusing at a physical table.
- **A Resolution Trace** — an ordered, structured record of every step the resolver applied (kind, source cast, target, before → after). The game resolves from it and the player-clarity surface (map tickets #282/#283) renders it, from a single implementation.

The central commitment is the **determinism invariant**: a round's outcome is a pure, deterministic function of its rolls, its Cast Log, and active effects, with nothing applied by side-effect that can't be reconstructed from the log. This is what makes three otherwise-hard things cheap — round replay (Time for Brew) becomes re-running the resolver over a modified Cast Log, counterspell-unwind becomes marking a cast negated and re-resolving, and player clarity becomes reading the trace. It also forces `resolved_value` to be de-overloaded into named fields as a precondition.

The dead enum values `persistent_modifier_delta` and `persistent_modifier_swap` (zero cards, zero readers) are retired as part of the first rebuild migration.

## Considered

- **Tweak the fan-out in place** — add the ~14 missing capability classes as new `effect_kind` values and readers following the existing pattern. Rejected: the fan-out itself is the prime suspect for both "messy application" and "players can't tell what happened this round", and the cross-cutting gaps (immunity/ward layer, counterspell-unwind, true round replay) bolt on badly. Lower regression risk short-term, but doesn't move the subsystem anywhere better.
- **Maximally lazy resolver** — model roll transforms too as resolver choices over always-recorded extra rolls. Rejected: awkward at a physical table and adds confusion for a small set of cards.
- **TS resolver over thin data RPCs** — more unit-testable, but moves authority off the database and away from RLS, and splits backfill/replay onto a different path than live play.

## Consequences

- Every one of the 29 currently-working cards has to be re-pathed through the new resolver; the rebuild spec must sequence that to keep regressions contained.
- `spell_active_effects` needs an explicit place under the invariant (log-derived cache vs first-class state) — see #292.
- The Resolution Trace becomes a stable contract consumed by the player-clarity work; changes to it ripple into #282/#283.
- **Amendment (#383, 2026-09-26; re-amended #438, 2026-09-30): the resolver decides a Heist, `finalize_layer` moves the card.** Tea Heist pins the victim's held card in the cast's `cast_inputs` (`stolen_instance_id`). The resolver's final phase (Phase 6) only *decides* and traces each Heist: a `card_heist` step reading moved, fizzled (the victim no longer holds the pinned card, having played it first, including as the counter) or countered (the cast ended negated). The card itself moves in `finalize_layer`'s commit step, in the same transaction as the resolution write, and only for a `moved` decision. The #383 text had `resolve_round` make the move itself; #438 changed that because, since ADR 0008, `finalize_layer` is the only committer, and since ADR 0007 `resolve_round`'s body also runs as a rolled-back dry run for every viewer's Provisional Recap. A move there would be one more write the dry run must roll back, and it would put the move somewhere other than where the round is committed. There is still one move site and one place that decides, and nothing else has to remember to call it. The hand cap still holds. If a crit draw has refilled the thief's hand since casting, the card lands as a keep-or-swap choice. With both of the thief's slots taken, the Heist fizzles (`thief_hand_full`). A decision the round keeps is made at the layer-0 exit, including a tie's. If the victim loses the card during the tie-break layers (a keep-or-swap discard), the kept Trace can read "moved" while `finalize_layer` finds nothing to move. That edge is accepted rather than re-tracing at every Layer. The Heist was **not** applied at cast time with an undo on negation: the thief could have played the card before a counter landed, leaving nothing to move back. The move is safe to repeat: it fires only while the victim still holds the card, so a re-run finds it with the thief and does nothing. A committed move is stamped `cast_inputs.heist_moved`. Round replay scraps only a round that has already resolved, so any move has already happened, and `_rr_scrap_round` moves the card back to the victim if the thief still holds it (into a keep-or-swap slot if the victim has drawn since, or back to the deck if both of their slots are taken), the same way a scrap reverses every other effect of the scrapped attempt's casts. The Tea Heist card itself stays spent.
- **Amendment (#425, spec #401 F1, 2026-09-30): the tea-maker precedence ladder and the modifier gain number.** Phase 5 of `resolve_round` picks the Tea Maker by one fixed ladder. The first tier that names someone wins. Since #451 the ladder lives in its own module, `_rr_select_tea_maker` (`db/sql/functions/`), which `_rr_resolve_eval` calls with the layer-0 Resolution Summary and which returns one selection result (outcome, Tea Maker, brewer source, modifier gain, tie pool, Trace steps); tier 0 is the single `_rr_is_brewer_candidate` predicate every tier asks:
  - **Tier 0: `brewer_immunity` filter.** A filter applied *inside* every tier below, not a pass of its own. An immune candidate at any tier counts as no match, and selection falls through. The Earl of Earl Grey is the one exception: an override naming the Earl first passes the title to the override's caster, and the ex-Earl then brews. If everyone is immune and there's no override, immunity gives way and a Tie-Break Reroll runs among all participants.
    - *Live since #428 (The Last Cuppa).* Phase 5 reads the live `brewer_immunity` rows directly, never through the Phase 2 ward filter. A declared number goes to a non-immune roller of that number if there is one. An immune override target, whatever the mode, falls through to the default pick; it does not revive an earlier override, since last-cast-wins has already chosen. "All participants" in the give-way tie means every Participant not excluded from the round. Each skip that changed the pick is a `brewer_immunity` Trace step naming the tier (`declared_number`, `tea_maker_override`, `lowest_roller`), and the give-way is one `all_immune` step. Dispel-resistance is a separate property of the row, `spell_active_effects.is_undispellable`, which every dispel path skips; The Last Cuppa has both, the Earl has neither, and neither has Tea Cosy (#434, a one-round row from the card's `duration_rounds = 1`).
    - *Live since #429 (Earl of Earl Grey).* The title is a `brewer_immunity` row with `mode: earl`, unbounded via `persist`. **One Earl per room** is a read-time rule, not a constraint: `_rr_active_effects_as_of` treats only the newest live title row in the room as live, so a fresh Earl cast displaces the holder from the round it is cast in, and a countered cast displaces nobody. The **transfer** is decided in `_rr_select_tea_maker`'s override tier: when the winning override (any mode) names the Earl, and the Earl is immune only through the title and didn't cast that override, it emits an `earl_transfer` Trace step (extras `new_earl_player_id`, `forcing_card_name`) and returns an `earl_transfer` decision; the override then lands on the ex-Earl. As with a Heist (#438 amendment above), the resolver only decides: `finalize_layer`'s commit step writes the transfer (`_rr_apply_earl_title`), so the Provisional Recap's dry run never moves the title. The new holder's row hangs off the override cast, and the commit step stamps every displaced title row `spell_active_effects.ended_in_round_id`, so a later dispel of the new Earl can't hand the title back. `_rr_scrap_round` clears that stamp for the scrapped round, and the new row goes with the override cast it deletes, so a replay hands the title back.
  - **Tier 1: `declared_number_tea_maker`.** Unchanged. It never triggers an Earl transfer.
  - **Tier 2: `tea_maker_override`, last cast wins** (`cast_at desc, seq desc`). The mode is a closed set, `highest_modifier | highest_roll | chosen | prev_round_highest | conditional_chosen`. A CHECK on both `spell_card_effects` and `spell_casts` rejects any other (or a missing) mode. The overrides are walked newest first; one that can't act never enters the contest: it leaves a no-op `tea_maker_override` Trace step with an `override_reason`, and the next-newest override is considered, so it can't beat an earlier one. `prev_round_highest` (Last Drip, #426) names the highest layer-0 roller of the room's most recent resolved round (ties: lowest `modifier_snapshot`, then lowest `player_id`). If there's no such round, or that player isn't a Participant this round, it is inert (`override_reason` `no_previous_round` / `target_absent`). *(Superseded by the #470 fall-through below.)* `conditional_chosen` (PG Tipped, #427) enters only if its condition holds; otherwise the step reads `after` = `condition not met`, with `override_reason` `condition_not_met` and extras `override_condition`, `target_roll`, `caster_roll`. PG Tipped's only condition is `target_below_caster`: the target's layer-0 roll after the roll-input shim is lower than the caster's. A player with no layer-0 roll fails it. An override's named player honours a Phase 1 redirect, the same as a modifier cast does in Phase 4a; a redirected PG Tipped therefore names its own caster and fails. PG Tipped carries `modifier_gain: 0`, so the target gains nothing only when PG Tipped itself forces the brew (the #380 reading of "Target gains no modifier from this round"). A `chosen` override with `effect_params.picker = 'lowest_roller'` (Tea Party Revolt, #430) takes its target from the Revolt Pick (`cast_inputs.revolt_picked_by` records who picked, traced as `picked_by`). With no pick it never enters: `override_reason` `pick_abandoned` when stall abandoned it (the cast is negated, but still traced unless a counter negated it), or `pick_pending` in a dry run before the pick.
    - *Last Drip fall-through amendment (#470, 2026-10-08): a deliberate rule change.* Last Drip no longer goes inert when the previous round's winner can't make tea. It walks the previous round's layer-0 rollers in the same order (highest value, then lowest `modifier_snapshot`, then lowest `player_id`) and names the first who is a Participant this round and not Roll-Exempt. An absent winner and an exempt one fall through the same way. Before this, an exempt previous winner was named anyway, and an absent one made the card inert. Brewer Immunity is unchanged: it is still the Brewer Candidate predicate at this tier, applied to whoever the walk names, so an immune pick falls through to the default as with any override. The card is inert only with no previous resolved round (`no_previous_round`) or when nobody in that round's roll list qualifies (`no_eligible_roller`); `target_absent` is no longer emitted. The `tea_maker_override` step carries `passed_over` (`[{ player_id, reason: absent | roll_exempt }]`, in roll-list order) whenever anyone was skipped, inert or not. The rule lives in one read, `_last_drip_target`, which `_rr_select_tea_maker` resolves the card through and which `get_last_drip_preview` exposes for the cast-time notice. The notice is a preview of the round as it stands: a later declare-in or Roll Exemption can change who is named, and the Trace stays the record.
  - **Tier 3: Loose Leaf roll-off.** Applied after selection, keyed to the final Tea Maker, whichever tier named them.
    - *Live since #431.* Casting Loose Leaf in the layer-0 Reaction Window records a `named_tea_maker_rolloff` Cast Log row aimed at its caster (no active effect: it only lasts the round, and a counter negates it in Phase 1). `_rr_select_tea_maker` checks it after the default pick, so it is keyed to whoever any tier named. The opponent is the second-lowest layer-0 roller among the named player and the Brewer Candidates, ordered by post-shim roll, then composed modifier; every player other than the holder sharing the second-place (roll, modifier) is an opponent, so a tie for second-lowest sends them all into the roll-off rather than being broken by `player_id`. With fewer than three in that order (a two-player round, where the "second-lowest" is the top roller), or with the holder alone second-lowest, the card is inert: a no-op `named_tea_maker_rolloff` step (`rolloff_reason` `no_second_lowest`) and the named player brews. Otherwise the step reads `after` = `rolloff` (extra `rolloff_opponent_ids`, listed by player id for a stable order) and selection returns the unfinished outcome `rolloff`, with no brewer and `tied_player_ids` = [holder, ...opponents]. `finalize_layer` commits it exactly as it commits a tie (`advance_round_layer`) and returns a tie-shaped outcome marked `rolloff: true`, so the existing tie broadcast, modal and flow run it; the next Layer's plain lowest pick (no spell logic, #219) decides it with normal modifier gain, and a tied roll-off goes to another Layer. An Earl transfer decided alongside a roll-off is written at the roll-off commit, since the deciding Layer's resolve returns none. Only layer 0 is checked: Layers above 0 skip tea-maker selection (#219), so a holder who loses an ordinary Tie-Break Reroll, or the roll-off itself, gets no further roll-off.
    - *Exempt holder (#433).* A holder with a Roll Exemption has no layer-0 roll, so isn't in the order. If they are named Tea Maker (say, by their own Loaf of Lipton), the opponents are the rollers tied at second-lowest among the others, which needs at least two of them. Exempt players are never opponents. In the roll-off Layer everyone rolls.
  - **Tier 4: default lowest roller** (`_rr_pick_lowest`). Immune players are left out of the candidate pool, and exempt players have no roll.
    - *Live since #433 (Roll Exemption, Loaf of Lipton).* Exemption is not a Brewer Candidate rule. The dice-based tiers read only layer-0 rolls, so an exempt player never matches a declared number, `highest_roll`, `highest_modifier` or the default pick. A `chosen` override can still name them. The exemption is the catalog flag `exempt_from_rolling: true` on the cast, read by `_rr_roll_exemptions`; it backs `get_expected_layer_roller_ids` and one `roll_exemption` Trace step per skipper (`before` `rolls` → `after` `skipped`). A cast group negated in a closed layer-0 Reaction Window exempts nobody, so a countered caster rolls late (ADR 0008).
  - **Pre-ladder rule:** a round with a live, payable Brew Debt skips tea-maker selection entirely.
    - *Live since #432 (Brew IOU).* `_rr_select_tea_maker` asks `_brew_debt_due` first. In a debt round the Debtor is the Tea Maker with normal gain, `brewer_source` is `brew_debt`, and one `brew_debt` Trace step (`after` = `brewer`, extra `brew_debt: paid`) points at the Brew IOU cast. See the Brew Debt amendment below.
  - `targeting_skip` (Cloud of Cream), `forced_reroll`, `lowest_gains_highest_modifier` and the ward phase are orthogonal to the ladder. `targeting_skip` only steers the `highest_modifier` pick and doesn't interact with the new modes (`prev_round_highest`, `conditional_chosen`).

  **Brew Debt amendment (#432, spec #401, design #382, 2026-10-01): the first resolver state that crosses rooms and days.** Until Brew IOU, a round's outcome read only its own room: its rolls, its Cast Log and the room's active effects. A Brew Debt is owed by a *player*, in whatever room they next play, on any later day. It is still not stored as state of its own. Two columns on the round that resolved record what made its Tea Maker brew, when a later round needs to read it back: `rounds.brewer_source` (`brew_iou` / `brew_debt`, null otherwise) and `rounds.brewer_source_cast_id`. `finalize_layer` writes them with the resolution: (`brew_iou`, cast) when a Brew IOU override (a `chosen` override flagged `creates_brew_debt`) actually named the Tea Maker, and (`brew_debt`, cast) on the round that pays. A Brew IOU that was countered, out-ranked, or fell through on an immune target records nothing. So does one whose target went on to a Loose Leaf roll-off, since the roll-off, not Brew IOU, then decides who brews. A debt is **live** while some round has (`brew_iou`, cast) and no round has (`brew_debt`, cast). `_brew_debt_due(round)` answers "does this round pay a debt, and whose?" and is the one read used everywhere. It searches across all of the Debtor's rooms, but never between the Test Room and a real room. It counts only rounds resolved before this one closed. It returns the oldest debt of a non-excluded Participant who has no Brewer Immunity as of this round, and only while the round has no layer-0 roll. The determinism invariant widens accordingly: a round's outcome is a pure function of its rolls, its Cast Log, the active effects, **and the Brew Debts its Participants owe**. Those debts are themselves derived from earlier rounds' committed resolutions. Replay and deletion need no special case. `_rr_scrap_round` clears `brewer_source` on the scrapped round, so scrapping the paying round makes the debt owed again. Scrapping the Brew IOU round also deletes its cast (FK `ON DELETE SET NULL`), so the debt never existed. Deleting a round has the same effect. A debt round has no expected rollers (`get_expected_layer_roller_ids`), so it resolves at close without a Reaction Window (ADR 0008). An immune Debtor plays the round normally and still owes. With several Debtors present, the oldest non-immune debt pays. A Debtor who owes twice pays one debt per round. A Late Declare only converts a round while nobody has rolled, which `declare_in_late` already enforces.

  **Carried Effect amendment (#472, 2026-10-07): the second resolver state that crosses rooms and days.** A multi-round card (`spell_cards.duration_rounds` > 0) now follows its *target* into later rooms, so a day's end, or the target sitting a round out, no longer burns its duration. Rooms are one per day and players are global, so the row stays where it was cast (`spell_active_effects.room_id`) and is **derived** into later rooms at read time, not copied: `_rr_active_effects_as_of` also returns an earlier-room row for the same target while the target's **Participation Clock** is still below the duration. The clock (`_rr_participated_rounds_elapsed`, now counted across rooms by `rounds.started_at`) replaces the room-wide `_rr_effect_rounds_elapsed` for every `duration_rounds` card, and Marked for Brew's and the Courage Token's windows fold into the same count, keeping their after/from-cast offsets. An effect with no duration (`rounds_remaining` NULL: rest-of-day wards, the Earl title, The Last Cuppa) stays in its day's room, and `room_players.modifier` still starts each day at 0: only the effect carries, and the resolver applies it to the target's rolls in whichever room they play. Like a Brew Debt, a Carried Effect never crosses between the Test Room and a real room. A carried effect on the target is dispellable from any room, and a Round replay re-evaluates it as of the replayed round, which counts once on the clock. Bitter Leech is two-sided: it ticks on the *target's* clock, and the caster's gain lands only if the caster also took part that round, otherwise it is lost. The determinism invariant widens again: a round's outcome is a pure function of its rolls, its Cast Log, the active effects (including those carried from earlier rooms), and the Brew Debts its Participants owe, all derived from committed earlier rounds, so replay and deletion still need no special case. *Rejected: copy-on-entry*, writing a fresh `spell_active_effects` row into the target's room when they first take part there. It would keep every reader's `room_id` filter, but the copy is mutable state that scrap, replay and admin deletion would each have to undo. *Consequence, accepted:* because it is derived, an admin deleting an earlier round the target took part in lowers their count and so lengthens the effect, and deleting the round holding the source cast removes it, the same way a Brew Debt behaves.

  The Tea Maker's gain is now a **modifier gain number** rather than a yes/no, and it flows from `resolve_round(uuid)`'s `modifier_gain` through `finalize_layer` into the resolution write `resolve_round(uuid, text, integer, integer)` and on to `rounds.brewer_modifier_gain`. `null` means the normal `cups_made`, `0` means no gain, and any other value is used as given (e.g. `2 * cups_made`). An override sets it from `effect_params.modifier_gain`, or from `effect_params.modifier_gain_multiplier` times `cups_made` (Loaf of Lipton's double gain, #433); the legacy `no_modifier_gain: true` reads as `0`. A `block_earned_modifier` ward on the Tea Maker forces it to `0` over any override value. The yes/no stays only as a compat alias: `no_modifier_gain` in the resolver output, and the `resolve_round(uuid, text, integer, boolean)` overload that delegates to the integer one. `_rr_base_modifier` sums `brewer_modifier_gain` (#395), so a 0 or doubled gain survives every modifier recompute.
