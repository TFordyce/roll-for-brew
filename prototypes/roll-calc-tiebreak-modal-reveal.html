Prototype — tie-break as a modal + dependent reveal row

Take 2 on issue #162, simplified after the team confirmed (issue #219) that spell effects and reaction casts never apply to a tie-break reroll. What's left to test here is purely the interaction model: tied players roll via a modal, not an inline banner section, and the outcome appears as a second row directly under the tied player back in the main reveal list, indented right with a connector to read as dependent on the row above — both independent of spell effects entirely now. Switch "Viewing as" below to see a tied player's own device (gets the modal) vs a spectator's (just watches the row fill in).

    Findings

    Does the rich calc line fit without shrinking?
    Yes, trivially — because it never has to live in a 96px tile at all anymore. The reroll renders at the reveal list's full row width, so #167's d20-icon/boxed-total treatment needed zero adaptation from what RoundReveal already ships for layer 0. Now that it's also guaranteed to never carry a discarded die or effect badge (#219), it's an even simpler element than take 1 was squeezing in.
    Does the modal work for the tied player, and not get in a spectator's way?
    Yes in this fixture — "Viewing as" a tied player shows the modal immediately (blocking, matches how a tied player has no other useful action available); every other perspective (the other tied player, spectators) sees no modal, just the pending row updating live once the broadcast lands. That split maps cleanly onto the existing selfPlayerId-vs-others pattern TieBanner already uses today for showing the roll input only to the tied player it belongs to.
    Does the dependent-row connector read as "depends on the row above" at a glance?
    Reasonably — the indent plus a short corner-line under the avatar makes the relationship legible without a label, though it's only tested here with one reroll layer. A second tie (rare, but the game allows chained rerolls) would need to decide whether it nests a third indented row or replaces the second one in place — not fixture-tested here.
    Is there still anything worth "rich" about a tie-break roll now?
    Only the d20 icon and boxed total as decoration — no discarded die, no boon/bust badge, ever, per #219. Worth asking whether that decoration is even worth keeping for a call site this plain, versus just the bare roll + modifier = total text RoundReveal already uses elsewhere for anything that isn't layer 0 — a design call for whoever implements this, not something this prototype needs to settle.

    Decision

    1. The modal + dependent-row interaction model still looks worth doing on its own merits — separable from the spell-effects question that originally motivated take 1, and now simpler to build since the reroll content itself is guaranteed plain.
    2. Real implementation is still a genuine scope jump from a tile tweak: RoundReveal.tsx currently has no concept of layer>0 rolls or tie state at all — it'd need to grow both, plus a modal component and its own roll-submission flow separate from TieBanner's existing one. TieBanner/PlayerTile may end up retired for this call site entirely rather than adapted.
    3. Depends on #219 shipping first — no point building the dependent-row plumbing against a data model that (until #219 lands) still lets a reroll carry a discarded die/effect badge it shouldn't.
    4. Not yet filed as its own issue — this file is the reference point for that write-up whenever you're ready to move on it.
